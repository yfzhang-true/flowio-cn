## 二、技术路线

1. **数据采集（P2 起）**：协议层的数据流式输出即采集器。标注场景：正常 / 松管 / 堵口 / 不同执行器，录 CSV。
2. **离线训练**：Keras 小模型（CNN 或自编码器，目标 10–100KB）→ int8 量化 → TFLite。
3. **部署三选一**：
   - Edge Impulse（网页平台，官方 ESP32-S3 支持，导出 C++ 库）——起步最快；
   - ESP-DL / ESP-NN（乐鑫官方，S3 SIMD 加速）——性能最优；
   - TFLM 直连——最通用。
4. **推理循环**：压力 50–100Hz 采样 → 1–2 秒滑窗 → 推理 5–50ms（S3 上）→ 结果上报协议层/小程序。

## 三、架构铁律

**TinyML 不进安全关键路径。** 闭环控制 = 确定性 PID；超压保护 = 硬规则；TinyML = 并行观察者，
输出异常分数/分类给应用层。理由：模型会错、规则不会；可解释性 = 可辩护性。
同时警惕 Bonsai 陷阱：每个模型必须有明确的客户价值（省售后钱 / 报表增值），拒绝"为了 AI 而 AI"。

## 四、竞争意义

FlowIO 无任何 ML 能力，且结构上不可能有（单人学术项目 + 封闭高层）。
"内置 AI 泄漏检测 / 训练质量评估"是软件层差异化，配合上市后的数据回流，
构成 FlowIO 结构性无法跟进的护城河（它没有商用用户群 = 没有数据来源）。
