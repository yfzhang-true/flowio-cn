## 1. 产品定义 V1.0

| 项 | 规格 | 说明 |
| --- | --- | --- |
| 端口 | 5 路气动输出（快插接头，2~3mm 管） | 对标 FlowIO |
| 动作 | 充气 / 释放 / 保压 / 测压 | 第一版不做负压 |

| 高级功能 | 压力闭环充气、任务序列、多设备、OTA | 分别对标 inflateP / 序列 / 多 FlowIO / 升级 |
| 供电 | V1：12V/2A 适配器；V2：锂电池便携版 | 降低首版复杂度 |
| 安全 | 机械泄压阀 + 固件超压保护 + 故障全关态 | 见 4.4 节 |

### 2.1 为什么是 7 个阀（对原规格的一处修正）

隔膜泵内部有单向阀，气体不能倒流。只靠"1 进气阀 + 5 端口阀"时，软体执行器（接在泵出口侧）**没有通往大气的释放路径**——开进气阀通的是泵入口，帮不了排气。FlowIO 的出口阀就是干这个的。所以必须加第 7 个阀（排气阀，接在汇流板上），否则"释放"功能不成立。保压仍然免费：常闭阀断电即密封。

## 4. 硬件架构要点

1. **电源树**：12V 输入 → 阀/泵母线（12V）→ buck 3.3V（MCU+传感器）。上电默认全关（常闭阀+PWM=0），这是"安全态"的物理基础。
2. **阀驱动统一走 PWM 通道**（FlowIO 踩过的坑：PWM/数字写混用会出时序 bug）。开启 100%，500ms 后降保持占空比（按阀规格实测标定，参考值 60–70%）。
3. **5 传感器同址问题**：订货时选配不同 I2C 地址；不够用就挂 TCA9548A 分通道。
4. **安全设计**（三层）：
   - 物理层：机械泄压阀兜底超压；总保险丝；适配器反接保护。
   - 固件层：任何传感器超阈值/失联/I2C 错误 → 立即全关进入安全态并报警；看门狗。
   - 状态层：32 位状态字对外广播，异常位置位。
5. **预留**：V2 电池版留充电管理焊盘；泵位留双泵布局（未来 INFLATION 双泵配置升级）；I2C/UART 扩展口。

## 5. 固件架构（ESP-IDF + FreeRTOS）

```
应用层    任务序列引擎 | 闭环控制任务 | OTA | NVS 参数
协议层    二进制指令帧(魔数+命令+端口位掩码+参数+CRC) ←→ BLE服务 / WiFi(TCP+mDNS) / 串口CLI
动作层    inflate / release / hold / sense + 配置门禁 + 状态字维护 + 节能管理
HAL层     LEDC-PWM阀驱动(开/保持两档) | 泵PWM | I2C传感器(含稳定延时) | 状态LED
```

直接继承 `02-气动控制核心逻辑.md` 的设计：端口位掩码 + set/open/close 三胞胎语义、32 位状态字、每元件启动时间表、动作前先停止、非阻塞闭环三要素（幂等/归属判断/耗时统计）、测压前 ≥10ms 稳定时间、传感器降级不瘫痪整机。
协议层补上 FlowIO 自己承认的缺陷：每条指令都可请求状态字回报。

## 6. 上位机生态

- **微信小程序**（核心差异化）：扫码/BLE 搜索连接 → 端口卡片式控制（压力实时值、动作状态）→ 拖拽式任务序列编辑器 → 压力曲线图 → OTA（WiFi 模式）→ 多设备管理。小程序蓝牙 API 直读写 Characteristic 即可，二进制帧用 ArrayBuffer。
- **Python SDK**（bleak/http）：面向科研用户，对标 FlowKit 生态位。
- 串口 CLI：调试期人眼可读命令（借鉴"ASCII 动作码"精神）。
