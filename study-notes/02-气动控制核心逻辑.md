# 气动控制核心逻辑笔记（基于 FlowIO 公开库的自主整理）

> 性质：功能性描述，用自己的话写的，不含任何 FlowIO 代码。
> 用途：作为自主设计 ESP32-S3 气动控制板的逻辑输入。
> 事实依据：`FlowIO_Library_2026.03.23` 源码（980 行）+ CHI'21 论文 + softrobotics.io 文档。
> 整理日期：2026-09-19。

## 1. 硬件模型（从代码反推）

FlowIO 标准版的执行器/传感器配置：

| 元件 | 数量 | 驱动方式 | 控制引脚（Feather nRF52832） |
| --- | --- | --- | --- |
| 隔膜泵 | 2（泵1=充气向，泵2=抽真空向） | PWM 调速（0–255） | 15、16 |
| 端口电磁阀（常闭） | 5（每端口 1 个） | PWM（开=255，保持≈170） | 12、11、10、9、6（端口1→5） |
| 进气阀（常闭） | 1（大气→泵入口侧） | 同上 | 5 |
| 出口阀（常闭） | 1（泵排气侧→大气） | 同上 | 14 |
| 压力传感器 | **1 个共享**（MS5837-30BA，I2C 0x76，接在汇流板上） | I2C | SDA/SCL |
| 状态灯 | 1×NeoPixel + 1×蓝色 LED | 数字/PWM | 8、4 |
| 软关机 | 拉高即切断系统电源 | 数字 | 13 |

**与我们规格的关键差异**：FlowIO 是"2 泵 + 7 阀 + **单**传感器"，我们规划的是"1 泵 + 6 阀（1 进气 + 5 端口）+ **每端口独立**传感器（I2C）"。我们没有抽真空泵（第一版不做负压），也没有出口阀——但**出口阀的"释放"职能必须保留**，详见第 4 节。

## 2. 五种配置的真实含义（重要洞察）

软件层面的配置枚举只做两件事：
1. **门禁**：配置不对时动作函数直接空操作（例如 INFLATION_SERIES 配置下调 `startVacuum` 无效）；
2. **选择释放阀**：释放时开哪个阀由配置决定（见第 4 节）。

串联/并联的差异**完全在气路接管（物理）**，软件对 SERIES 和 PARALLEL 的行为几乎一致（都是双泵同开）。"半容量"动作 = 双泵配置下只开一个泵。

| 配置 | 充气 | 抽真空 | 半容量 |
| --- | --- | --- | --- |
| GENERAL（通用，出厂默认） | 泵1 | 泵2 | 不适用 |
| INFLATION_SERIES / _PARALLEL | 泵1+泵2 | 不允许 | 泵1 |
| VACUUM_SERIES / _PARALLEL | 不允许 | 泵2+泵1 | 泵1 |

对我们的启示：**配置机制 = 一个枚举 + 动作门禁表**，成本极低但防呆价值高；单泵产品可以用同样的机制表达"仅充气"模式，并为未来双泵升级预留。

## 3. 基本动作的执行序列

每个高层动作开始前都先执行一次"停止动作"（关两个方向阀、关指定端口阀、双泵停转），保证从干净状态起步。端口参数是一个 5 位位掩码（bit0=端口1 … bit4=端口5）；全 0 视为无效输入，直接忽略。

### 充气（GENERAL 配置）
1. 停止当前动作
2. **开进气阀**（大气进入泵入口）
3. 按位掩码**开端口阀**
4. 泵1 以给定 PWM 运转

### 抽真空（GENERAL 配置，我们第一版不做，仅记录）
1. 停止当前动作
2. **开出口阀**（泵排气侧通大气）
3. 开端口阀
4. 泵2 运转

### 释放（完全被动，不开任何泵）
1. 停止当前动作（泵全停）
2. 开端口阀
3. 按配置开方向阀：
   - 充气型配置 → 开**出口阀**（排高压）
   - 真空型配置 → 开**进气阀**（放进空气破真空）
   - GENERAL → 两个都开

充气释放靠泵内单向阀防止倒流，气体经出口阀排出。**我们的单泵设计必须有等效的排气通路**（泄压阀或泵持续反转都不可靠，建议保留一个专用泄压阀）。

### 保压（hold，没有独立函数，就是"停止动作"）
关全部方向阀 + 关端口阀 + 停泵。常闭阀断电即密封，端口阀一关，软体执行器内压力就被封住。**保压 = 全关**，这是常闭阀方案的核心红利（断电即保压，安全）。

### 端口阀的三种操作语义（值得照抄的设计）
- **set**：按掩码逐位设定（1 开 0 关）——写全部
- **open**：只开掩码为 1 的端口，其余不动——置位语义
- **close**：只关掩码为 1 的端口，其余不动——清位语义
三胞胎 API 避免了"想关 3 号口却把别的口也关了"的经典 bug。

## 4. 阀保持电压节能机制（省电关键，必学）

电磁阀开启瞬态需要全电压（PWM=255），吸合后维持只需 ~2/3 电压（默认保持值 170/255）。库的做法：

1. 每个阀记录"本次开启起始时间"；
2. 主循环里周期性调用节能函数：任何阀开启超过阈值（默认 500ms）且尚未进入保持态 → 把该阀 PWM 降到保持值，打上"已优化"标记；
3. 任何对该阀的新操作（开/关）都会清除"已优化"标记；
4. 支持运行中改保持值：已处于保持态的阀也立即应用新值。

注意一个坑：FlowIO 全程用 PWM（analogWrite）驱动阀，即使全开全关也不用纯数字写——因为同一引脚混用两种写法在恢复时序上会出 bug。**我们的驱动层也应统一用 PWM 通道写阀**。

## 5. 状态跟踪设计（对上位机/小程序很有用）

- **16 位硬件状态字**：bit0–4=端口1–5 开/关，bit5=进气阀，bit6=出口阀，bit7/8=泵1/泵2 运行，bit10=蓝灯，bit11=传感器。任何驱动层操作同步维护对应位。
  → 一次读一个 uint16 就能回报整机状态，通信开销极小。我们的 BLE/WiFi 协议应保留这个设计（ESP32 上可扩成 32 位：加 5 路传感器有效位、泄压阀、错误位等）。
- **每元件启动时间表**：记录每个阀/泵本次激活的 millis() 时刻，停转清零。用于节能判断和"动作耗时"统计（如压力闭环返回充气用时）。
- **全局最后状态变化时刻**：供自动关机等功能判断空闲。

## 6. 压力测量

### 单传感器分端口测压技巧（FlowIO 的巧妙之处）
FlowIO 只有一个接在汇流板上的传感器，测"某个端口的软体执行器压力"的办法：
1. 关两个方向阀、停双泵（隔离汇流板与大气/泵）；
2. 只开目标端口阀（软体执行器与汇流板连通）；
3. 等 10ms（实测 8ms 不够、9ms 边缘、10ms 安全——气路传压稳定时间）；
4. 读一次压力。

这是"顺序扫描 + 流体复用"的思路。**我们每端口独立传感器后不需要这个技巧**，但这个"测压前先隔离"的思想对管路有串扰的场合仍有参考价值；且它提示：压力采样要给气路一个稳定时间（≥10ms 量级）。

### MS5837-30BA 读数流程（可从数据手册独立重写）
1. 上电复位（10ms）→ 读 7 个 16 位 PROM 校准系数 → CRC4 校验（失败报错码 200）；
2. 每次测压：触发 D1（压力）转换 → 等 ~2ms → 读 24 位 → 触发 D2（温度）转换 → 等 ~2ms → 读 24 位；
3. 按数据手册公式做一阶换算 + 二阶温度补偿（低温/极低温/高温三段）；
4. 输出五种单位（mbar 为基准，其余换算）。

错误码体系：2=I2C 无应答，200=CRC 失败，201=未初始化就请求读数，202=中途掉线（恢复连接后自动清码）。传感器未接时库照常工作（activate 返回 false，读数输出 -1）——**气动功能和传感功能解耦，坏了传感器不瘫痪整机**，这个降级设计值得保留。

## 7. 三字节指令协议（公开！之前以为私有，实现在库里）

格式：`[动作字符] [端口位掩码] [PWM值]`，返回一个 float（无效时 999.9）：

| 动作码 | 含义 | 动作码 | 含义 |
| --- | --- | --- | --- |
| `!` | 停止动作（保压） | `o` | 只开端口阀 |
| `+` | 充气 | `c` | 只关端口阀 |
| `-` | 抽真空 | `ff` | 软关机 |
| `p` | 半容量充气 | `r` | 红色状态灯 |
| `n` | 半容量抽真空 | `b` | 蓝色 LED |
| `^` | 释放 | `??` | 立即测汇流板压力 |
| | | `?端口` | 隔离法测指定端口压力（见第 6 节） |

设计要点：ASCII 动作码使协议人眼可读、串口监视器可直接手打调试；单字节端口位掩码天然支持多端口并行；返回值统一为 float 简化了固件→蓝牙层的透传。**我们的 WiFi/BLE 协议可以直接借鉴这个"字符指令 + 位掩码 + 参数"的精神**（改成二进制帧或 JSON 都行，思想不变），并补上 FlowIO 自己 TODO 里承认的缺陷：指令层无法回报硬件状态字（我们应让每条指令可请求状态回传）。

## 8. 两种控制模式（开环/闭环）的写法范式

### 时间开环（阻塞式）
动作 → 延时 N 毫秒 → 停止动作。简单但阻塞主循环，只适合简单场景。

### 压力闭环（非阻塞状态机，精华所在）
设计成一个**需要被反复调用**的函数，靠两个标志协调：
- 公开的"完成"标志：完成后函数变空操作，用户手动复位才能再次触发（即使换端口也要复位——标志与端口无关）；
- 私有的"运行中"标志 + 硬件状态字比对：防止并发调用打架；并处理"外部强行停止动作"的边界（检测到全部端口关闭就把运行标志自动落下，避免死锁）。

时序：首次调用→启动充气；后续调用→读压力，未达标继续，达标→停止动作、返回从开进气阀到停泵的总耗时（返回前必须先取启动时间再停止，因为停止会清零时间表）。

多端口差异化目标压力：5 个目标值对应 5 口，哪个口先达标就先关哪个口的阀，全部关闭后统一收尾。

**对我们的启示**：ESP32 上更自然的做法是 RTOS 任务 + 事件，但"用状态字比对判断动作归属、用完成标志做幂等、边界情况显式处理"这三条是框架无关的工程经验。

## 9. 防呆与工程细节清单（小但值钱）

- 端口参数全 0 → 静默忽略（防止 `startInflation(0)` 误触发）；
- 泵号越界 → 静默忽略（注释特别警告：数组下标 -1 会读到相邻内存，可能恰好是一个合法引脚号，导致物理损坏且极难复现）；
- 上掩码外的高位先清掉再比较（位运算比较的前提）；
- 配置不对 → 动作静默空操作（防呆，但也在文档里承认该给用户反馈——我们应加错误回报而非静默）；
- 阀统一走 PWM 通道（见第 4 节）；
- 构造函数把所有输出初始化为 PWM=0（全部关闭态）。

## 10. 映射到我们的 ESP32-S3 产品规格

| FlowIO 机制 | 我们的对应设计 |
| --- | --- |
| 2 泵 + 进气/出口阀 + GENERAL 配置门禁 | 1 充气泵 + 进气阀 + **新增泄压阀**（承担 FlowIO 出口阀的释放职能），配置枚举只留"标准充气模式"并预留扩展 |
| 端口位掩码 + set/open/close 三胞胎 | 原样保留此 API 语义（ESP32 上位掩码直接映射 GPIO 组） |
| 全关=保压（常闭阀红利） | 相同；另加"安全态"概念：任何异常→全关（断气断电即安全） |
| 500ms 后阀降保持电压 | 必学：LEDC PWM 分两档（开启 100% / 保持 ~67%，按我们阀的规格实测标定） |
| 16 位状态字 | 扩展为 32 位：5 端口阀、进气阀、泄压阀、泵、5 传感器有效位、错误码位 |
| 单传感器 + 隔离扫描测压 | 每端口独立 I2C 传感器（如 XGZP/MPRLS 多路），无需扫描；保留"测压前稳定 ≥10ms"的采样纪律 |
| MS5837 流程 | 换成我们选型传感器的手册公式，结构照旧：复位→校准/CRC→D 转换→温补→单位换算→错误码 |
| 3 字节 ASCII 指令协议 | 借鉴精神：短指令 + 端口位掩码 + 参数；载体换 BLE/WiFi 帧，并补上状态字回报（FlowIO 的已知 TODO 缺陷） |
| inflateP 非阻塞闭环范式 | RTOS 任务 + 状态机，保留幂等/归属判断/耗时统计三要素 |
| powerOFF 软关机引脚 | ESP32 用 deepsleep + 电源使能脚实现同类"一键断气断电" |
| 236 个示例的组织方式 | 按场景分类（按钮控制/自检/压力测试/显示），我们也应给 SDK 配同等级示例库 |
