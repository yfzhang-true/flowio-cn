\chapter{验收实录：数字孪生与实物}
\label{ch:acceptance}

验收在本书里不是附录，而是一等公民的写作方式——每一节对应一张验收工单，验收产生的截图、波形与实测值即书稿图源。本章分上下两篇。\textbf{上篇}是已经完成的一半：板还在嘉立创产线上，但数字孪生的全套产品（前端、固件逻辑、BLE 契约、SDK）已经可以逐项验收，六张软件侧工单 A101--A106 于 2026-10-02 全部判定 \texttt{pass}，本章按"操作步骤 $\to$ 判定 $\to$ 证据"的固定体例逐节实录。\textbf{下篇}是等待硬件的一半：二十四张硬件工单（A201--A224）与六张标定工单（A301--A306）已生成模板，回板后按 15--30 分钟一张的节奏执行，产物直接回流本章与第~\ref{ch:product} 章。上篇证明"软件这边没有欠账"，下篇规定"硬件那边怎么还账"。

\subsection{A101 装配叙事与爆炸跟随}
\textbf{操作步骤}：启动 \texttt{server.py} 后打开 \texttt{http://127.0.0.1:8000/}，首屏即装配叙事——五部件（上壳/器件阵/PCB/下壳等）从四散位飞入合体约 1.5\,s，随后进入呼吸悬浮；拖动运输条爆炸滑杆至 50\%，记录分解态截图。自动化侧由 \texttt{test\_webapp.js} 经调试钩 \texttt{window.\_\_t2} 读取渲染态：加载块断言五部件在场且收敛位移 $<$3\,mm，爆炸块断言 \texttt{setExplode(1)} 后部件位移 $>$10\,mm、系数平滑跟随 $k\!\approx\!1$、\textbf{流组每帧复制 PCB 位移}（流线端点绑定不断线）。

\subsection{A104 SDK 协议向量双向 + hello\_glove 冒烟}
\textbf{操作步骤}：\texttt{python -m unittest test\_protocol}（\texttt{sdk/python/tests/}）跑协议回归；\texttt{python examples/hello\_glove.py}（孪生模式）跑"充 $\to$ 保 $\to$ 释 $\to$ 抽"一个来回的最小冒烟。\textbf{判定}：\texttt{pass}——\texttt{vectors.json} 的 8 组黄金帧向量与固件 \texttt{test\_proto.c} 同参数构帧、逐字节相同；同 8 组 decode 往返还原 \texttt{cmd/ports/pwm} 三元组；坏 CRC/坏魔数/坏长度/参数越界四条错误路径各自由 \texttt{ProtocolError} 接住。向量表全文与"CRC 多项式写错"的纠错故事见第~\ref{ch:sdk} 章表~\ref{tab:sdk-vectors}（\S\ref{sec:sdk-vectors}）。

值得强调的是这组工单的取证形态：它没有截图，证据是\textbf{测试输出本身}——两侧对同一向量表双向编解码，任何一端漂移都会立刻红。hello\_glove 冒烟补的则是"五分钟上手"承诺的可兑现性（第~\ref{ch:sdk} 章 \S\ref{sec:sdk-hello}）。

\subsection{A105 固件 QEMU 冒烟 + 主机 33 测试}
\textbf{操作步骤}：\texttt{cmake + Ninja} 主机编译后跑 \texttt{firmware/tests/} 全量；\texttt{bash qemu\_smoke.sh} 跑整只固件冒烟。\textbf{判定}：\texttt{pass}——33 个主机测试全绿（动作层 10 / 闭环 7 / 协议 4 / TCA 8 / BLE 载荷 4），QEMU 冒烟九项 grep 判定全过：启动横幅、PSRAM 8\,MB、\texttt{F} 自检三步、\texttt{I 1 255}/\texttt{H 1}/\texttt{S 1} 应答、\texttt{L} 路由。两道防线的分工与实跑输出见第~\ref{ch:firmware} 章 \S\ref{sec:fw-tests} 与 \S\ref{sec:fw-qemu}。

这是六张工单里唯一"没有浏览器"的一张，却是对回板影响最大的一张：逻辑层在烧录前就带着 33 条断言的战绩上路，BRINGUP 里遇到的硬件问题才可能被\textbf{定位到硬件}，而不是与软件 bug 混作一团。

\subsection{A106 BLE 契约载荷向量（向量先验）}
\textbf{操作步骤}：跑 \texttt{ble\_tests.c} 四个主机测试（帧打包、负压小端、哨兵值、保留字节违例）。\textbf{判定}：\texttt{pass}——契约 \texttt{twin/BLE.md} \S 4.1 命令帧（0xA5 前缀 + CRC-8/ATM）与 \S 4.2 state 20\,B 小端载荷以向量形式\textbf{先验冻结}：负压 $-533$\,Pa 打包为 \texttt{EB FD} 小端、压力无效哨兵 \texttt{0x8000}、保留字节违例拒收。真机侧的 nRF Connect 扫描/写/订阅三步不在此单范围——那是回板后 A209 的活（第~\ref{ch:ble} 章 \S\ref{sec:ble-verify}）。

"向量先验"是这张工单的方法论价值：无线链路的正确性不必等天线，字节级契约可以在主机上先钉死；等真机到场时，A209 要验的只剩射频与连接管理本身。

\subsection{26 项目视审计：从截图到像素证据}
\label{sec:acc-visual}

断言读的是渲染态，但"看起来对不对"断言管不了——装配动画的手感、玻璃材质的层次、粒子在亮壳上的对比度，最终都要过\textbf{人眼}这一关。v2 交付按 F3 模式做强制目视：十张截图 \texttt{v2\_01}--\texttt{v2\_10}（首屏/爆炸 50\%/充气/静默/真空/热点卡/遥测抽屉/仿真浮层/断连态/恢复态），先机内像素审计——直方图、色簇、帧间差分，外加"浏览器投影走廊"校准（同一元素在浏览器坐标系与截图像素坐标系之间的映射带），共 26 项检查全数通过；再交 AI 视觉复核装配材质、UI 布局与热点卡内容，全部对上。断言、像素、AI 三层证据互不替代：断言防逻辑错、像素防渲染错、AI 复核防语义错。

断连态是目视审计里最有设计含量的一项（图~\ref{fig:acc-stale}）：停掉遥测源后，连续两次失败才置 \texttt{stale}（单次抖动不算），主场景流光淡出为底光、粒子淡出、状态行亮"遥测冻结"徽章——\textbf{不弹窗、不渲染过期值}（第~\ref{ch:host} 章 \S\ref{sec:host-telemetry}）。恢复后底光重新亮起、徽章消退。这一"安静的降级"哲学：坏消息用光的暗下来讲，比用弹窗讲更符合一台机器的体面。

审计也留下一条\textbf{已知事项}并维持裁定：气流粒子 \texttt{depthTest:false} + 高渲染序，保证"通道存在、气流喷出"在默认视角（管路被壳遮挡）下始终可见——代价是亮壳表面上叠加粒子的对比度偏克制。像素审计走廊内 38\,px 青簇可检出，判定不改（spec \S3.2 底光语义）。把这类"审过但保留"的记录写进书，与 pass/fail 一样是验收产物。

\subsection{验收工单机制：一张工单，两份产物}
\label{sec:acc-ticket}

上篇六张工单能"验收完即写完书"，靠的是机制本身。设计规格（\texttt{2026-10-02-acceptance-book-design.md}）把 BRINGUP 的 checkbox 与书稿 12 章的素材需求合流成 36 张\textbf{验收工单}（BRINGUP 现有 36 个未勾 checkbox——工单生成时为 30 个，后清单扩充，以现数为准）：每张是一个 YAML 文件，放在 \texttt{book/tickets/} 下、以工单号命名（\texttt{A\#\#\#.yaml}）——头部记录元数据（相位 \texttt{sw}/\texttt{hw}/\texttt{cal}、对应 BRINGUP 章节、汇入书稿章、状态、证据要求），\texttt{---} 之后是 Markdown 正文（操作步骤、实测值表、判定、素材管线指令）。一张工单完成等于两份产物落袋：BRINGUP 对应 checkbox 勾掉，书稿对应小节的图与数据就位。\textbf{fail 的工单同样入书}——"踩坑实录"专栏比 pass 更有教学价值。

管理工具 \texttt{ticket.py}（在 \texttt{book/tools/} 下，纯标准库实现，YAML 头按"一行一字段"手写格式解析、不依赖 PyYAML）用三个子命令覆盖全生命周期：

\begin{lstlisting}[basicstyle=\small\ttfamily, breaklines=true,
  caption={ticket.py 用法（自项目根）}]
python book/tools/ticket.py new A225 "新验收项" hw 9+ --book-ch 11   # 生成模板
python book/tools/ticket.py report                                  # 进度一屏
python book/tools/ticket.py set_status A205 pass                    # 更新状态
\end{lstlisting}

\texttt{report} 的实时输出即 36 张工单的总账（摘头尾）：

\begin{lstlisting}[basicstyle=\small\ttfamily, breaklines=true,
  caption={ticket.py report 输出（2026-10-02，摘录）}]
ID    phase  status   title
----------------------------
A101  sw     pass     孪生 v2 首屏装配叙事 + 爆炸滑杆
A102  sw     pass     电流/气流联动：I/V/S 命令差分截图
...   ...    ...      （A103--A106 软件侧全 pass）
A201  hw     pending  首电三测（万用表）
...   ...    ...      （硬件 24 张、标定 6 张全 pending）
A306  cal    pending  孪生对拍：闭环精度 + 数字孪生精度报告
----------------------------
合计 36 张（sw 6 / hw 24 / cal 6）：pass 6 · pending 30 · fail 0 · waived 0
\end{lstlisting}

软件侧六张（\texttt{pass}）即本篇 A101--A106 各小节与 \S\ref{sec:acc-matrix}、\S\ref{sec:acc-visual} 的实录来源；其余三十张的下篇总表见 \S\ref{sec:acc-hw-table}。状态机四态（\texttt{pending}/\texttt{pass}/\texttt{fail}/\texttt{waived}）中 \texttt{fail} 不算失败的项目、算\textbf{进书资格}，\texttt{waived} 留给"理性放弃并记录理由"的项——三者都会在书里留下正文。

\section{下篇：实物验收（工单驱动，待回板）}
\label{sec:acc-hw}

下篇的三十张工单在等一块板：嘉立创制板 5 片、贴装 2 片（主力 + 备用，第~\ref{ch:fab} 章下单实录）。这一篇先立好三样东西——执行节奏（\S\ref{sec:acc-workflow}）、工单总表（\S\ref{sec:acc-hw-table}）、首电安全门（\S\ref{sec:acc-firstpower}）——回板之日即可开工，边验收边把本章下篇从"总表"长成与上篇同体量的实录。

\subsection{回板后工作流：每张工单 15--30 分钟}
\label{sec:acc-workflow}

工单的粒度按"一个工作台上的一段专注时间"设计：执行 10--20 分钟，归档与写书 5--10 分钟。固定动线九步：

\begin{lstlisting}[basicstyle=\small\ttfamily, breaklines=true,
  caption={单张工单动线（spec 2026-10-02-acceptance-book-design.md §4）}]
领工单（ticket.py report 选 pending 头一张）
-> 照 firmware/BRINGUP.md 对应章节执行验收（截图/拍照/录数）
-> 产物拷入 book/figures/（图）与 book/data/（CSV）
-> 工单正文填实测值表 + 判定（pass/fail + 容差）
-> ticket.py set_status <ID> <pass|fail|waived>
-> BRINGUP.md 对应 checkbox 勾掉
-> 书稿对应章 .tex 增图/表/叙述（fail 走踩坑实录专栏）
-> xelatex 编译过 -> git commit
\end{lstlisting}

这个节奏的可贵之处在\textbf{不积压}：验收产物当天变成书稿，书稿编译错误当天暴露；三十张工单全部走完时，第~\ref{ch:acceptance} 章与第~\ref{ch:product} 章的实物素材同步齐稿——验收完成日即书稿主体完成日，这是"验收 $\times$ 专著一体化"设计的全部赌注。

\subsection{首电安全三测预告（A201）：万用表的唯一保留环节}
\label{sec:acc-firstpower}

三十张工单大多以"软件读数"取证（串口日志、遥测截图、示波器波形），唯有一张从上个世纪活到现在——A201 首电三测，工具栏里只有一只万用表。理由很硬：\textbf{软件无法保护你免于第一次上电的短路}。烧录、遥测、BLE 全部成立的前提是 5V/3V3 轨活着，而"轨活着"在首电那一刻只能用表说话。三测动线：

\begin{enumerate}
  \item \textbf{轨阻抗}：不上电，万用表二极管/电阻档测 5V 与 3V3 轨对地阻抗，排短路——贴装板的第一道闸，第~\ref{ch:fab} 章收货验收的延伸；
  \item \textbf{限量首电}：经限流（电源限流挡或 USB 电流表）首电，观察静态电流应为 mA 级而非安级——安级即回第 1 步找短路；
  \item \textbf{轨电压}：表笔确认 5V 与 3V3 电压在容差内（buck 空载输出对照第~\ref{ch:twin} 章 \S\ref{sec:twin-board} 的标称值），方可进入 A202 烧录。
\end{enumerate}

三测的实测读数与表笔照片按素材管线归档为 A201 证据。图~\ref{fig:acc-dmm} 与图~\ref{fig:acc-solder} 预置了它的取证形态——前者是万用表表笔对轨电压/对地阻抗的测量示例，后者是首电前的目检样张（U1 四侧焊脚与端子排焊接质量，正是收货三步中"目检"的放大版）；两张均为\textbf{实拍示例，回板执行 A201/A202 时替换为 P1 实测照}，图位与 caption 先行占座，素材管线（\S\ref{sec:acc-workflow}）到时只需换文件。它是整条动线的第一张工单，也是"数字孪生验收（上篇）"与"实物验收（本篇）"的分界：从此以后，每一个数字都长在真板上。

\section*{本章小结}
上篇用六张 \texttt{pass} 工单证明了"回板之前，软件无欠账"：装配叙事与爆炸跟随（A101）、三态差分联动（A102）、四电路重算（A103）、SDK 双向向量（A104）、固件两道防线（A105）、BLE 先验冻结（A106），背后是 44 断言矩阵、26 项目视审计与三层证据哲学（断言防逻辑错、像素防渲染错、AI 复核防语义错）。下篇用三十张 \texttt{pending} 工单规定了回板之后怎么还账：15--30 分钟一张的九步动线、按 BRINGUP 九章排序的总表、以及一只万用表守着的首电安全门。上下两篇合起来，才是"验收"的完整定义——\textbf{已完成的可复核，未完成的可执行}。
