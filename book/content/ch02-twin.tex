\chapter{孪生先行：物理建模与仿真}
\label{ch:twin}

PCB 下单到回板之间有两三周的空窗。传统流程里这段时间只能等；FLOWIO-CN 的流程里，这段时间被数字孪生填满：\texttt{firmware/twin/} 目录下的板级物理模型（\texttt{twin\_api.c} 气动 + \texttt{board\_model.py} 电气）让固件命令、遥测面板、BLE 契约、上位机 SDK 在真实硬件到来之前就全链路跑通。回板那天，孪生不是被抛弃的脚手架，而是与真机\textbf{对拍}的标尺——两者的偏差本身就是产品交付物（第~\ref{ch:product} 章的"数字孪生精度报告"）。

本章讲三件事：孪生的架构为什么必须"逻辑与物理分离"；气动物理如何从工程近似（v1）升级为文献形式（v2/v2.1）；以及如何诚实地管理模型参数的成色——"理论值"与"实测值"用徽章区分，不让演示数字冒充实测。

\section{逻辑与物理分离：一份 pn\_core，两个世界}
\label{sec:twin-arch}

孪生的第一条架构原则：\textbf{逻辑层与物理层彻底分离}（图~\ref{fig:twin-3d}）。逻辑层是 \texttt{pn\_core}——命令分发、状态机、闭环控制、调度器，它与烧进 ESP32-S3 的固件是\textbf{同一份代码}；物理层是 \texttt{mock\_hal} 之后的仿真世界：阀位图不再驱动真实线圈，而是驱动一套气动微分方程，压力传感器的读数不再来自 XGZP6897D，而是方程的积分值。

\section{从 v1 到 v2：让模型长出文献的形状}
\label{sec:twin-v2}

孪生的第一版物理（v1）是工程一阶近似：充气压头线性衰减 $(1-p/P_\text{max})$、抽真空对称、被动排气按时间常数指数衰减。它的优点是直觉、可调；缺点是\textbf{形状不对}——真实气动系统的高压差段是恒流（音速阻塞），充气曲线是 $\sqrt{\ }$ 压头而不是线性渐近，开阀数量会改变升降压速率。演示够用，对拍不够。

\section{核心方程与 \texttt{dP/dt} 实现}
\label{sec:twin-dpdt}

v2 的每个 50\,ms tick 做四件事：容积合成、孔口流量求和、多变定律积分、传感器钳位。核心代码（\texttt{twin\_api.c}，注释为源码原有）：

\begin{lstlisting}[language=C, basicstyle=\small\ttfamily, breaklines=true,
  caption={twin\_api.c 物理积分核心：孔口流量、choked 钳位与多变定律（节选，泄漏项从略）}]
float V = V_MANIFOLD_L + popcount(ports) * V_PORT_L;   /* V = V_m + n·V_p（L） */
float P = p + P_ATM_KPA;          /* 表压 -> 绝对压 */
float net_q = 0.f;                /* 净流量 L/s，充为正 */

if (pump_on && inlet_on) {        /* 充气：孔口形式渐近死点 */
    float PR = PUMP_P_MAX_KPA + P_ATM_KPA;
    net_q += PUMP_C * duty * sq_pos(P * (PR - P));
} else if (pump_on && vent_on) {  /* 抽真空：对称形式渐近极限 */
    float Pm = (PUMP_P_MIN_KPA > VALVE_P_MIN_KPA ?
                PUMP_P_MIN_KPA : VALVE_P_MIN_KPA) + P_ATM_KPA;
    net_q -= PUMP_C * duty * sq_pos(P * (P - Pm));
}
if (vent_on && !pump_on) {        /* 被动排气/负压回充（choked 钳位） */
    float d = P - P_ATM_KPA;
    float f = P_ATM_KPA * d;                       /* f = P_low·ΔP（带符号） */
    float f_choked = P_ATM_KPA * (CHOKED_RATIO - 1.f) * P_ATM_KPA;
    if (f >  f_choked) f =  f_choked;   /* 高压差恒流：与 √ΔP 解耦 */
    if (f < -f_choked) f = -f_choked;
    net_q -= VENT_C * sqrtf(fabsf(f));
}
/* ……泄漏项：进气/排气阀密封面 + 端口侧泄漏（阀开才对汇流管可见）…… */
p += GAMMA * P / V * net_q * dt;  /* 多变气体定律：dp = γ·P/V·Q·dt（γ=1.2） */
if (p >  SENSOR_SPAN_KPA) p =  SENSOR_SPAN_KPA;   /* XGZP6897D ±100kPa 饱和 */
if (p < -SENSOR_SPAN_KPA) p = -SENSOR_SPAN_KPA;
\end{lstlisting}

三处细节值得放大。\textbf{其一，choked 段}：当上游与下游绝对压比超过 1.893（空气临界压比），孔口流速钳制在音速，流量不再随 $\sqrt{\Delta P}$ 增长——对应代码里对 $f=P_\text{low}\Delta P$ 的上下钳位。真机上它的可观测签名是：泄放初期降压速率近似恒定，之后才转入 $\sqrt{\ }$ 衰减尾。v1 完全没有这个现象，对拍时一眼就能识破。\textbf{其二，开阀瞬时等温混合}：端口阀 0$\to$1 的瞬间，汇流管气体与新接通的端口容积（初压取端口节点当前值）均压，$p \leftarrow \frac{P_1V_1+P_2V_2}{V_1+V_2}-P_\text{atm}$——密封 60\,kPa 时开一个新端口，压力阶跃下降且幅度按 $V_m/(V_m+V_p)$ 可预测，这是验收用例之一。\textbf{其三，$\gamma{=}1.2$}：多变指数介于等温 1.0 与绝热 1.4 之间，取自 Xavier 2022~\cite{Xavier2022Frontiers} \S4 的实验值——快速充放气介于两者之间，这是文献给出的折中。

\section{参数成色：孪生模型也会"说谎"}
\label{sec:twin-params}

注意 $C_\text{vent}$ 的成色标注：它是全表最"虚"的数——裸阀 Cv 0.05（0520D）/0.10（0520F）全开流导比它高约两个数量级，实物排气会显著更快。SPEC 不掩盖这一点，而是写明"到货重标"。参数表还诚实处理了时间尺度：370 泵空载流量 2.2\,L/min 直驱 7\,mL 汇流管理论充压远快于孪生当前时标——孪生时标锚定的是 FlowIO 文档级充气曲线（秒级，真实执行器容积下成立）。对不上实物的原因被写进文档，而不是藏进代码。

参数表之外还挂着一条\textbf{如实建模的已知缺陷}：固件的超压保护阈值定在 120\,kPa，而传感器量程上限是 100\,kPa——压力永远到不了 120 才会被钳在 100，真机上这个保护\textbf{永远无法触发}，是一段客观存在的盲区。孪生没有"顺手修好"它，而是原样建模（钳位在 $\pm100$，保护阈值 120 原样传入 \texttt{pn\_check\_overpressure}），并在文件头注释里标注"待用户决策阈值"。理由与黄徽章一脉相承：孪生的职责是忠实复现当前设计——包括它的缺陷——让缺陷在对拍与验收里暴露，而不是在仿真里被无意识地"优化"掉。孪生若悄悄比真机更安全，它就失去了作为测试台的可信度。阈值本身最终裁定建议降到 90\,kPa（量程内留裕量），列入回板前的待决策清单。

\section{v2.1 多节点端口模型：一个 bug 牵出的物理修正}
\label{sec:twin-v21}

v2 交付后，用户实测报了一个 bug：G 闭环运行时汇流管压力缓缓下降，而界面上的"端口 1 压力"纹丝不动。排查结论出乎意料——\textbf{不是显示 bug，是物理模型的 bug}：物理层只有汇流管单一气压节点，所谓"端口压力"只是前端变量（阀开时拷贝汇流管值、阀关时冻结），根本没有仿真状态。更深一层：端口泄漏被无条件作用于汇流管节点，而物理上\textbf{阀关之后，端口侧的泄漏对汇流管传感器不可见}——用这样的模型生成的训练数据，含有物理上不成立的签名。

v2.1 的修正（\texttt{twin\_api.c} 中 \texttt{s\_port\_p[5]} 数组）：

\begin{enumerate}
  \item 每端口独立节点：关阀瞬间快照汇流管压力，此后独立演化（自身密封微漏 + 端口泄漏孔口流）；开阀时与汇流管同节点；
  \item 开阀混合的端口初压改用端口节点真值（原假设大气压）；
  \item 端口泄漏移到端口侧：阀开对汇流管可见、阀关不可见；
  \item 基线微漏条件修正为"泵侧密封即适用"（含 H 诊断保压的端口全通态）；
  \item 新增 CLI \texttt{H <ports>} 命令（泵侧密封 + 端口保持通）——泄漏诊断的标准工况。
\end{enumerate}

修正同时暴露了一个采样率声明错误：每 tick 一个采样点实际是 20\,Hz，原标注 50\,Hz，斜率特征因此虚高 2.5 倍。两处修正一并落地后，孪生行为与"阀是隔离边界"的物理直觉终于一致：关阀后端口压力沿自身泄漏曲线漂移，汇流管读数不再被下游污染。\texttt{pn\_twin\_port\_pressure()} 把端口节点导出到 \texttt{/api/state.ports\_p}，前端端口卡片直接显示真值，原先的"冻结 hack"删除。

v2.1 的涟漪还波及了当时搭载在孪生上的 TinyML 泄漏检测：训练工况改为 H 语义、标签改为物理可观测的 $\Delta$ 分级、采样率修正并入、类平衡采样——终值准确率 95.73\%、normal 召回 98.6\%、major 召回 95.3\%（零漏报为 normal）、模型 18\,KB。但这个功能最终在 2026-10-02 随用户裁定\textbf{整体下线}：对标 FlowIO，官方平台没有出厂级泄漏诊断，白牌客户也未必愿意为此付钱；后端、接口、前端三层拆除归档，CLI \texttt{L} 命令退化为应答 \texttt{leak=off}。这段插曲值得记录的不是模型指标，而是方法论：\textbf{孪生的价值不随搭载功能的下线而消失}——泄漏注入接口（\texttt{pn\_twin\_set\_leak}）保留至今，用于出厂筛选工况的复现与孪生自测；被裁掉的是产品功能，留下的是物理能力。

\section{传感器模型：对着手册逐条校准}
\label{sec:twin-sensor}

压力传感器 XGZP6897D-C 的孪生模型不是拍脑袋的 $\pm100$\,kPa 钳位就完了。对照 CFSensor 官方手册 V1.1 逐条核对，发现原实现有三处\textbf{到货必炸}的驱动级错误（表~\ref{tab:twin-xgzp}）：I2C 地址、读法与换算全错。这正是"孪生先行"的另一种价值——在真机到来之前，靠文档把驱动层的雷排掉。

  \centering
  \caption{XGZP6897D-C 驱动级三处修正（对照手册 V1.1，2026-09-23）}

传感器的其余手册参数进孪生的取舍同样有据：量程饱和 $\pm100$\,kPa 已建模；精度 $\pm2.5\%$FS 属系统性分量，经上电零点自校准消除（装配指南 bring-up 步骤）；零点漂移 $\pm1\%$FS 按校准后残差 $N(0,0.5)$ 建模；响应 2.5\,ms@OSR1024 与上电 24\,ms 均 $\ll$ 50\,ms tick，忽略；量化步约 0.1\,Pa，忽略。

\section{板级电气孪生：BOARD\_PARAMS 与黄徽章}
\label{sec:twin-board}

气动孪生之外，回板前还建了\textbf{电气孪生}（\texttt{board\_model.py}）：8 路阀线圈的 RL 电流、5V/3V3 双轨负载、一阶热惯性、600\,s 环形历史。阀电流用解析式而非数值积分：开通 $\tau_\text{on}=L/(r_\text{coil}+r_\text{ds})\approx1.78$\,ms，关断经 SS14 续流回路 $\tau_\text{off}=L/r_\text{coil}\approx1.79$\,ms，电流过零被二极管反向截止钳位——与仿真套件 \texttt{sim\_engine} 的续流 ODE 是同一物理量，防"双源漂移"。

\begin{lstlisting}[language=Python, basicstyle=\small\ttfamily, breaklines=true,
  caption={board\_model.py 的 BOARD\_PARAMS：每个参数带成色注释（摘自源码）}]
BOARD_PARAMS = {
    "r_coil": 14.0,    # [假设-行业典型] 阀线圈电阻 14Ω (5V/14Ω ≈ 0.356A 稳态)
    "l_coil": 25e-3,   # [假设] 阀线圈电感 25mH
    "rds": 0.040,      # [手册] AO3400 @ VGS=3.3V 导通电阻 ~40mΩ
    "vbus": 5.0,       # [标称] USB 5V 总线
    "vf_ss34": 0.31,   # [手册] SS34 肖特基正向压降 (5V 轨串入)
    "vout3v3": 3.269,  # [实测] buck 标称输出
    "load_reg": 0.012, # [仿真] buck 负载调整率 (V/A)
    "i_pump": 0.35,    # [假设] 泵电机平均电流
    "theta": {         # [手册] 热阻 ℃/W
        "cpu": 35.0,
        "buck": 130.0,
        "mos": 350.0,
    },
}
BUCK_EFF = 0.876      # [仿真] buck 效率
\end{lstlisting}

模型的其余两个状态量同样一行一个物理假设：逻辑负载电流 0.43\,A 由三部分估算——ESP32 峰值约 0.24\,A、TCA9548A 与 CH340 等外围合计补足（成色：估算，回板电流钳实测）；板级热惯性按一阶模型推进，时间常数 30\,s，三个热节点（CPU/buck/MOS）各挂手册热阻 35/130/350\,$^\circ$C/W。温升的意义在验收侧：A215 工单要用红外热像对照修正这三条热阻，MOS 那 350\,$^\circ$C/W 是全板最孤注一掷的数字——SOT-23 封装的天然弱势，设计上靠"8 路阀不同时满占空比"的使用假设兜底。

电气参数的成色管理与气动侧同一套思想，汇总成\textbf{物理校准状态矩阵}（设计规格书 \S10）：每个模型参数区分两件事——\textbf{结构正确性}（方程是不是物理规律，如多变定律、RL 解析式）与\textbf{参数校准度}（数值是不是本机实测），不混谈。成色分四档：实测 $>$ 手册 $>$ 仿真 $>$ 假设。全项目电气参数中最硬的一档在仿真引擎里：buck 分压比 R4/R5 就是板上实阻（3.27\,V 输出的来源，见第~\ref{ch:schematic} 章修正 \#11）；最软的一档是阀线圈 R/L——BOM 未锁传感器与阀型号前只能用行业典型值。

矩阵的呈现约束写进了前端：遥测面板角落固定显示\textbf{黄色徽章}"模型参数：理论值（未本机标定）"；回板后跑完六项电气校准（A211--A215：阀线圈万用表+LCR 实测、RDS 示波器反推、ESR 纹波反推、效率四线法、$\theta_{ja}$ 红外对照、ESP32 电流钳），改 \texttt{BOARD\_PARAMS} 常量，徽章转绿。\textbf{不让演示数字冒充实测}——这是孪生的诚信底线，也是它作为产品文档的可信度来源。

与板级模型配套的还有四个电路的行为级仿真（\texttt{sim\_engine.py}，无 ngspice 环境下的自研状态机 + SVG 输出）：电源效率、输出纹波、温升、I2C 时序。四电路的达标判据与一次 I2C 告警案例的复盘见第~\ref{ch:acceptance} 章 A103 工单；参数重算接口（\texttt{POST /api/board/sim}）允许前端改元件值即时重跑。

\section{到货之后：calibrate\_pump.py 三实验协议}
\label{sec:twin-calib}

孪生参数表里所有"借值"与"假设"都指向同一个收尾动作：到货实测。\texttt{calibrate\_pump.py} 把这个动作固化成三个实验的协议（P0 装配完成、共地确认后执行）：

\begin{enumerate}
  \item \textbf{实验 A，充气死点}：堵死充气口（或全密封），\texttt{I 31 255} 连续 30\,s，每秒记录汇流管压力——末端渐近值即 $P_R$ 实测；
  \item \textbf{实验 B，真空死点}：堵死气路，\texttt{V 31 255} 连续 30\,s，每秒记录——末端渐近即 $P_\text{min}$ 实测（验证 $-53.3$ 的阀窗假设）；
  \item \textbf{实验 C，升压曲线}：接实际执行器容积，\texttt{I 1 255} 从 0 充到死点，每 0.5\,s 记录——用于拟合 $C_\text{pump}$。
\end{enumerate}

记录格式统一为无表头两列 CSV（\texttt{time\_s, pressure\_kPa}）；脚本读入后做渐近估计（末端中位数）并检查收敛（末端抖动 $<0.5$\,kPa 才算到达死点，否则提示加长实验时长），输出\textbf{直接可抄的 \texttt{\#define} 修改建议}——含建议值与数据文件名注释，对照 \texttt{twin\_api.c} 改两行即完成一次参数升级。实验 C 的 1--4\,s 平均升压率与 FlowIO 标定参照值（2\,s$\to$19 / 4\,s$\to$35\,kPa，约 8--9\,kPa/s）对照，明显更快则说明 $C_\text{pump}$ 需上调。改完常数后的回归门槛写在脚本尾注里：\texttt{build\_twin.sh} 与 \texttt{run\_tests.sh} 全绿。三个实验、一个脚本、两行宏——这就是"黄徽章转绿"在气动侧的全部操作量；它对应的验收工单是 A216--A218（第~\ref{ch:acceptance} 章）。

电气侧的校准动线同构但更手工：六项实测（表~\ref{tab:twin-board}）改的是 \texttt{BOARD\_PARAMS} 常量块，无需新脚本——校准工具的价值在于协议与判定门槛，不在于代码量。

\section*{本章小结}
孪生先行的本质是把"等板子"变成"先跑起来"：逻辑层与物理层分离让固件、前端、SDK 在回板前全链路演练；气动物理以文献形式（多变定律 + ANSI 孔口 + choked + 容积耦合）重写，再用多节点端口模型修正了"冻结端口压力"这类物理不成立的行为；电气侧以 BOARD\_PARAMS 成色注释与黄徽章机制管理参数可信度。回板之后，孪生与真机对拍——偏差本身就是交付物。
