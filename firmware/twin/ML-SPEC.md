# ML-SPEC — 泄漏检测 TinyML 训练管线 v1.0

> 状态：**待用户审查**（2026-09-22）
> 前置：SPEC 15 决策已批准（泄漏检测 / Edge Impulse+TFLM / 并行观察者）
> 物理基础：PHYSICS-SPEC v2 已实施（孔口方程 + 泄漏注入 API 已上线）

## 1. 目标

在 **无 ESP32 硬件** 的条件下，利用数字孪生批量生成标注压力数据，
训练泄漏检测 TinyML 模型，产出可直接烧录的 int8 TFLite / Edge Impulse Arduino 库。
**到货后仅需烧录 + 真机域差距校准（预计 1 天）。**

## 2. 管线架构

```
┌─────────────────────────────────────────────────────────┐
│ Stage 1: 数据工厂（孪生 → CSV）                          │
│  Python 脚本 → HTTP API 驱动孪生 → 工况矩阵批量仿真      │
│  → 每条场景 = 1 段压力时间序列 + 标签                    │
├─────────────────────────────────────────────────────────┤
│ Stage 2: 特征工程（CSV → 训练集）                        │
│  滑窗切分 → 特征提取（斜率/方差/频域）→ train/test 划分  │
├─────────────────────────────────────────────────────────┤
│ Stage 3: 模型训练（两条路径）                             │
│  A. Edge Impulse 网页平台（推荐起步）                    │
│  B. 本地 Keras → TFLite int8（精细控制）                 │
├─────────────────────────────────────────────────────────┤
│ Stage 4: 评估                                           │
│  混淆矩阵 / ROC / 每类准确率 → 达标→导出 / 不达标→调参  │
├─────────────────────────────────────────────────────────┤
│ Stage 5: 导出                                           │
│  Edge Impulse → Arduino C++ 库（可直接编译进固件）       │
│  或 Keras → TFLite int8 → model 分区文件                │
└─────────────────────────────────────────────────────────┘
```

## 3. 数据设计（Stage 1 详细）

### 3.1 场景矩阵（工况参数空间）

| 参数 | 取值 | 说明 |
|------|------|------|
| 泄漏元件 | 0-6（7 元件各一）+ 无泄漏 | 8 类 |
| 泄漏系数 k | 0.05, 0.1, 0.2, 0.5 | 4 级严重度 |
| 初始操作 | 充气中 / 保压中 / 释放中 / 静止 | 4 种工况 |
| 初始压力 | ~20, ~40, ~60 kPa | 3 档 |
| 端口开合 | 1 口 / 3 口 / 全关 | 3 种 |
| 随机噪声 | ±0.5, ±1.0 kPa 高斯 | 2 档（模拟传感噪声） |

**总场景数**：8 × 4 × 4 × 3 × 3 × 2 = **2,304**（每类 ~288 条，平衡采样）

### 3.2 每条场景数据格式

```csv
# metadata
scenario_id,leak_component,leak_k,operation,initial_pressure,ports_open,noise_sigma
# time series (50Hz, 10 秒 = 500 点)
timestamp_ms,sensor0_kpa,valve_state,pump_duty
0,40.12,7,255
20,40.35,7,255
...
```

### 3.3 API 驱动流程（每条场景）

```
1. POST /api/reset                    → 清零状态
2. POST /api/cmd "I 7 255"           → 启动充气（或 S/R/V 按工况）
3. 等待达到目标初始压力                → 轮询 /api/state
4. POST /api/leak "<idx> <k>"         → 注入泄漏（或跳过=正常）
5. 每 20ms 采样 /api/state.sensors[0] → 记录 10 秒压力曲线
6. 附加噪声（模拟传感噪声）
7. POST /api/leak "reset"             → 清理
```

**耗时估算**：每条 ~12 秒（10s 采样 + 2s 启动/清理）→ 2304 条 ≈ **7.7 小时**
→ 可后台跑，或降采样至 1000 条 ≈ 3.3 小时（首版推荐）

## 4. 特征设计（Stage 2 详细）

### 4.1 滑窗参数

| 参数 | 值 | 依据 |
|------|-----|------|
| 窗口长度 | 2 秒（100 点 @50Hz） | 泄漏瞬态可见 |
| 步长 | 0.5 秒（25 点） | 50% 重叠，增样本 |
| 每场景产出 | ~16 个窗口 | (500-100)/25 + 1 |

### 4.2 特征向量（每窗口 → Edge Impulse / Keras 输入）

| 特征 | 维度 | 计算 |
|------|------|------|
| 原始压力序列 | 100 | 直接送入 1D CNN（Edge Impulse 推荐做法） |
| （备选）统计特征 | 8 | 均值/方差/斜率/最大偏差/前5频段能量 |

**首发用原始序列 + 1D CNN**——Edge Impulse 对时序分类的默认方案，无需手工特征。

### 4.3 标签编码

| 类别 | 编码 | 含义 |
|------|------|------|
| normal | 0 | 无泄漏（k=0） |
| leak_minor | 1 | k ≤ 0.1（可忽略/缓慢） |
| leak_major | 2 | k ≥ 0.2（需维护/报警） |

**首发用 3 分类**（normal/minor/major），不按元件分——先解决"有没有问题"，
再解决"哪里有问题"（P2 多分类）。

## 5. 模型设计（Stage 3 详细）

### 5.1 架构（Edge Impulse 默认 1D CNN）

```
Input (100,) → Conv1D(16, 3) → ReLU → Dropout(0.2)
             → Conv1D(16, 3) → ReLU → Dropout(0.2)
             → MaxPool(2) → Flatten
             → Dense(32) → ReLU → Dropout(0.2)
             → Dense(3) → Softmax
```

参数量 ~10K → int8 量化后 ~10KB → **远小于 256KB model 分区**

### 5.2 训练超参

| 参数 | 值 |
|------|-----|
| Optimizer | Adam (lr=1e-3) |
| Loss | categorical_crossentropy |
| Epochs | 30（EarlyStopping patience=5） |
| Batch size | 32 |
| Train/Test split | 80/20（按场景分，非按窗口分——防泄漏） |

### 5.3 验收指标

| 指标 | 目标 |
|------|------|
| 正常类准确率 | ≥ 95%（误报少——不能总报警） |
| 重泄漏类召回率 | ≥ 90%（漏报少——安全问题） |
| 整体准确率 | ≥ 90% |
| 模型大小 | ≤ 50KB (int8) |

## 7. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 孪生数据域差距（到货后需校准） | ①噪声注入模拟传感特性 ②到货后录 50 条真机数据微调 |
| 7.7 小时数据生成太慢 | ①降采样至 1000 条 ②后台运行 ③已验证 /api/reset <50ms |
| Edge Impulse 免费档限制 | 备选 Keras 本地路径完全等价 |
| 泄漏速率太慢难检测 | LEAK_C 已标定（k=0.2 → 3+ kPa/s vs 基线 <0.5）——特征可区分 |

## 8. 明确不做的事（YAGNI）

- 不做 P 波/频域手工特征（1D CNN 自动学习）
- 不做多元件定位分类（首发 3 类，P2 扩展）
- 不做异常检测/自编码器（有标签数据充足，监督分类更高效）
- 不做在线学习/联邦学习（P4 远期）
- 不做 IMU/麦克风融合（仅压力数据）
