## 1b. 官方图解爆炸视图精读（2026-10-05 用户供图，架构级结论）

**两套装配栈**（此前文档按"单栈"理解，已纠正）：

- **左栈=泵模块**：Enclosure-Pump → Pumps Driver PCB → Micro Pump → LiPo → Base-Pump。
  泵自带壳/驱动板/电池，通过管路+连接器与主模块对接（右栏 S/M/L 三档：37/90/251g）。
- **右栈=主模块**（上→下）：Enclosure-Main（顶壳 5 气口）→ **Microcontroller 独立小板**
  → Main Driver PCB（**阀排+硅管+压力传感板载**）→ **LiPo 电池整薄层** → Base-Main。

**对 P1.1 的直接影响**：
1. **"阀装板上是原版同源设计"**——爆炸图铁证，决策点 1a 竖装（阀阵+歧管+顶出气口）方向正确；
2. **MCU 独立小板**为原版 nRF52 模块化遗产，我们 ESP32-S3 单板等效集成（少一层板，成本/可靠性优）；
3. **电池层取消**后的 PCB 下方空间（原版放 LiPo）在我们设计中可让给走线/地平面，无结构负担；
4. **泵横躺形态**（左栈 Micro Pump 平置）为 T6 泵舱布局参考——我们泵舱在主板同层侧面减振软垫上；
5. **气动六动作**（Inflation/Vacuum/Release/Hold/Pressure Sense/Flow Variability）
   与我们 10 通道逐一映射：充=D 通电+F 分配、吸=泵吸气口路、泄=F 通电、保=全断电(NC)、
   测=XGZP 分时、变速=Q14 PWM——**语义 parity 完整**；
6. **一体化 vs 模块化=显式取舍**：原版泵/主分体换来"压力流量分档选配"，代价是两套壳两套电池；
   B2B 康复手套场景要的是开箱即用单器件 → P1.1 一体化，模块化留 P2 生态位（与原版扩展模块生态对齐）。

## 2. P2 候选件的空间/拓扑约束（框架直接消费）

- **阀排（M2-1 选型，JLC 真值入 devices.json）**：placement=EDGE_OUT；port.type=pneumatic；
  气口朝外侧同向阵列；与驱动 MOS（Q3-Q10 已有）加**域亲和边**（同列就近）；
  与歧管加 SPATIAL_SAME_DOMAIN 边；板上高 ≤14mm（壳预算）。
- **压力传感**：SURFACE 域；近歧管（亲和边）；I2C 地址与 TCA9548A 通道拓扑入网表。
- **~~LiPo+充电~~（已裁撤）**：用户明确外供 5V 不用电池充电（2026-10-04）——原版"电池藏
  板下薄层"的负 z 空间利用思路留档备查（若 B2B 客户提出便携需求再评估，届时优先
  超低矮 LiPo + 充电 IC 近电源口）；
- **IMU**：SURFACE；远离 L1 电感（min_distance 断言 ≥5mm，磁场干扰）。

## 3. 框架支撑模式（每项集成 = 加数据 + 加断言）
1. 选型 → jlcpcb MCP 摄取真值 → devices.json 加条目（dims/port/placement）；
2. 布局 → placement_advice（网表电气边 + 域亲和）出候选 → 人工/KiCad 定位；
3. 守门 → L5 自动断言：朝向/贴边/碰撞/槽匹配/钻孔避让/装配顺序；
4. 交付 → make_case/meshes/flows/assembly 全链重生成 + L1-L5 全绿。

## 4. 排期（spec §7 M2 里程碑）
M2-0 前置：本框架（T1-T7）交付 + P1 板到货 BRINGUP 通过（供电/8 路带载实测）
→ M2-1 选型（1 次会话）→ M2-2 布局约束 → M2-3 P2 全链交付（原理图增量+布局+
外壳+孪生+L1-L5）。启动时点：P1 到货验证后。
